# 功能：画布上能做什么、怎么算

入口：[README](../README.md) ｜ 架构：[architecture.md](architecture.md) ｜ 接口契约：[api.md](api.md) ｜ 验收：[acceptance.md](acceptance.md)

页面原来只有"看"，2026-10-28 起加了编辑动作。第一到第九节是**看得见的东西**，第十节是动作与接口的对照表。

## 一、画布与视口

- **没有边缘上限**（主人原话：「画布大小没有边缘上限：随当前情况而定。」）：`nodes.pos_x/pos_y` 是世界坐标、**可以为负**，可以一直往外；拖动、双击空白建节点、批量落坐标都不往 0 夹。
- **画布多大由内容定**：节点摆到哪它就长到哪，没有固定宽高。视口（`<g id="viewport">`）只是观察窗口，平移/缩放改的是它，不改任何坐标。
- **底纹跟着视口走**：格子原点＝世界原点，`backgroundPosition = 平移`、`backgroundSize = 步长 × 缩放`；缩到 30% 时步长自动 24 → 96，免得糊成一片。底纹钉死在屏幕上就会露馅"画布就这么大"。
- **`±1000000` 只是防垃圾兜底**（`FreePos()`），拦的是手抖写出的 5e6 这类值，**它不是画布边界**。节点真跑丢了按工具栏「重置视图」——fit 按全部**看得见**的节点算包围盒。
- **缩放/平移**：滚轮缩放 0.3×–2.5×，锚在光标下的点；中键拖动平移；「重置视图」按内容自适应。这些全是前端视口状态，不进库。

## 二、手势与选择模型

一句话：**左键＝选中，右键＝菜单（拖出去＝连线），Delete＝删掉当前选中的那个**。

| 手势 | 结果 |
| --- | --- |
| 左键按住节点本体拖动 | 移动节点（多选时整组一起走），松手落库 |
| 左键点一下（不拖） | 选中节点 / 连线 / 组（三类互斥，右栏跟着切换） |
| Shift + 拖动 | 左右/前后吸附对齐（见第四节） |
| Shift + 点一下 | 加/减选（在 `pointerup` 里判定，不抢拖动） |
| 空白处拖出选框 | 框选；选框 <4px 当点击空白处理 |
| 右键点一下（**不拖**） | 出菜单（节点 / 组 / 链块各有各的菜单） |
| 右键按住拖出去（>4px） | 画临时线，拖到目标节点松手即成线（按住 Shift＝回边） |
| 双击节点/组/链块标题 | 快收快开（见第九节） |
| 双击空白 | 当场建一个默认节点 |
| 点击空白 | 取消当前选中（节点/连线/组/链块一律清），右栏清空 |
| Delete | 删除优先级：**连线 > 组 > 多选节点 > 单节点**；输入框里只删字 |

- 右键同一颗键兼两件事，用 **4px 位移**分界：按下先挂成"待连线"，拖出去才成立，没拖动就松手当点击出菜单。别用长按或二次点击区分——那条路会把手感和可测性一起弄坏。
- 拖动阈值 `DRAG_START = 3px`：1–2 px 抖动不算拖动，否则点击会被吞。
- 输入框里的 Delete 不删图：`isTypingTarget()` 判 `input/textarea/select/contenteditable`（双击建节点后标题框是聚焦的，这条必须有）。
- 什么都没选时按 Delete 什么都不做，也不拦浏览器默认行为。

## 三、拖动：跟手、不回弹

**回弹是两个 bug 叠出来的**（留档防复发）：

1. **位置没写回图**：`moveNodeTo()` 只改渲染缓存与 DOM `transform`，`state.graph.nodes[].posX/posY` 还是旧值，而 `render()` 是按图节点重算布局的——任何一次重绘都摆回旧位置。修法：写 DOM 的同时把坐标写回图节点。
2. **松手后紧跟一次整图重绘**：`pointerup` 里 `await saveLayout()`，浏览器会在其后补一颗 `click`，`click` 处理器拿**还没落库的旧坐标**就 `render()`。修法：真拖动过就置 `state.suppressClick` 吃掉那颗 click（下次 `pointerdown` 复位）。

**跟手性**：`pointermove` 里**立刻**把节点 `transform` 写下去（位置同步生效），只有连线重绘交给 `requestAnimationFrame` 合并。两者都塞进下一帧就会有"拖一格、线慢半拍"。为什么会卡、怎么解的，见 [architecture.md](architecture.md) 第五节·性能设计。

## 四、Shift 吸附：两轴各四候选

`snapAxis()` 对**每个轴**分别算四种候选位移，取阈值 `SNAP_PX = 12` 内最近的一条：

| 轴 | 四个候选 | 参考线文案 |
| --- | --- | --- |
| 左右（x） | 左缘对左缘、右缘对右缘、左缘贴邻居右缘、右缘贴邻居左缘 | 左对齐 / 右对齐 / 贴到右侧 / 贴到左侧 |
| 前后（y） | 上缘对上缘、下缘对下缘、上缘贴邻居下缘、下缘贴邻居上缘 | 上对齐 / 下对齐 / 贴到下方 / 贴到上方 |

- 两轴**互相独立**，所以一次拖动可以同时吸成一列又一行，画两条橙色虚线（竖 + 横各一个槽）。
- 同宽同高节点下"左对左"与"右对右"是同一个坐标，真正让方向有区别的是那四条**贴靠**候选。
- 整组拖动时按**主节点**吸附，其余同位移；吸附是纯前端的，松手照常落库。

## 五、节点

- **双击空白建节点**：不弹表单，当场建「新节点 N」（work）并选中、右栏标题框自动聚焦，直接改名。要完整表单（多口）走工具栏「＋ 新建节点」。
- **点节点改属性**：右栏「属性」可改标题 / 一行目标 / 类型 → `POST /nodes/{id}/props`，只改给了的项，回带 `changed` 并写一条 `node-update` 事件；没差别不写事件。循环区不在这里改（见第八节）。
- **收纳三档**：`nodes.compact` 0 完整 / 1 仅标题 / 2 仅关键字（一行目标）。存级别而不是布尔，是为了以后加档位不用改表；接口也收 `collapsed=true` 当 1 用。尺寸从 `layout()` 里算（完整 214×88、收纳 140×40），所以端口均分、连线端点、框选命中、组框包围盒、fit 全都自动跟着窄卡片走。鼠标悬停用 `<title>` 给「标题 · 状态 · 一行目标」。
- **点节点高亮相连的线**：相连的线 `stroke-width: 3`，其余压暗到 `opacity: 0.14`；取消选中全恢复。只看连接关系（`state.selected` + 邻接），不额外存状态；组被收纳时，组外接到这组的线也算"它的线"。类名 `edge` / `edge-focus` / `edge-dim`，每次重绘按当前选中重算，所以拖完、刷新、切任务都不会留残余高亮。
- **接线区**：左缘＝进线口、右缘＝出线口，**口数可自定义（1–12，默认各 1）**，沿边等分；命中圈半径 14、看得见的圆半径 7。普通线挂在具体口上，回边挂底部中点。改口数在右栏「接线口」里填；缩到已挂线的口以下后端回 409 `port-in-use`。

## 六、连线

- **点线不是点它的 1.5px**：每条线额外画 16px 宽透明命中带（`data-edge-hit`），点它才算选中。
- **面板能改什么**：终点（起点不给改——要换起点就删了重画）、类型 `transfer`/`loop`、挂第几个出线口/进线口、**门控**（`auto` / `human` + 一句条件说明）。改走向会把两头节点的输入规则组按现存入边重算，组里不会留着已经不存在的边。
- **门控**：`human` 未点头时上游做完下游仍 `pending`，拒因 `gate-needs-confirm`；面板给「确认门控」按钮，点头后立刻放行并起步下游，重复点头幂等。视觉：未确认＝橙色虚线 + 「门控待确认」，确认后恢复正常并标「门控✓」。
- **已放行过的线冻结**：不许改走向/类型、不许删、不许事后加人工门控，只能放宽成 `auto` 与改备注（同一个原因码 `edge-already-released`）。

## 七、节点组

- **它是纯画布分组**：`node_groups` + `nodes.group_id`，画一个圆角虚线框 + 上方蓝色标签。**不进门、不参与执行、不改任何判定**——跟循环区（改执行语义）不是一回事。
- **建**：框选或 Shift 点击多选（≥2）→ 右键 →「建立节点组」。
- **三处抓手，拖哪个都是整组走**：**组名**（标签）、**组边缘**（框上那圈 16px 透明描边 `data-nodegroup-edge`）、收纳后的**牌**。按住＝把成员全选上再整组拖，落坐标只发一次批量请求；**按下没拖＝选中这个组**（右栏出组面板），右键＝组菜单。
- 组的框本身 `pointer-events: none`（只画不吃事件），所以**框里的空白照样框选、照样双击建节点**；只有那圈边是抓手。
- **删组两种口径**：默认**只解散**（清 `group_id` + 删组行，一个节点都不删）；`withNodes=true` 才连节点一起删，且要求整组都删得起，否则整批不动并点名（`node-group-not-deletable`）。组里少于两个成员自动散掉，不留"一个节点的组"。
- **收纳＝压成一块牌**：`POST /node-groups/{id}/collapse`（跟坐标一样只落库不写 events）。收纳后成员不画、**组内线不画**、**跨边界线收拢到牌上**（同一对只画一条，多条标 `×N`）；牌取成员包围盒左上角、214×64。
- **框选与 fit 都不骗人**：`nodesInRect` 跳过藏起来的成员，`重置视图` 按"看得见的节点 + 牌"算包围盒。
- 收纳态下拖动结束后会整图重排一次（收拢过的线要重算），这是唯一允许拖动后立刻重绘的场合。

## 八、循环区并进节点组：组＋回边＋检查点

不再有单独的"循环区"对象——**一个节点组声明了循环，它就是循环区**。

| 原来 | 现在 |
| --- | --- |
| `nodes.cycle_region` 字符串（成员归属） | `nodes.group_id`（组才是归属） |
| `cycles.region_key`（循环的身份） | `cycles.group_id`（循环挂在组上；`region_key` 退化成组名的显示镜像） |
| 回边要求「两端 cycle_region 相同」 | 回边要求「两端在同一个组，且那个组已声明循环」 |
| 一轮结束按 `cycle_region` 重置 | 按 `group_id` 把整组成员打回 pending、`cycle_epoch + 1` |
| 节点属性里改「循环区」 | 已废弃（400 并指路：圈进组 → 给组声明循环） |

- `POST /api/node-groups/{id}/loop {head, tail, limit}` 一次配齐三件套：写 `cycles`（带 group_id）、**自动连 tail→head 回边**、把成员 `cycle_region` 镜像成组名。
- `DELETE /api/node-groups/{id}/loop` 删回边与 `cycles` 行，**组留着**变回普通分组；回边已经放行过（进过下一轮）则拒绝。
- 循环组不能直接删（`group-is-loop`）：先撤循环再删组，避免"回边还在、循环没了"的半死状态。
- **界面**：不再画单独的紫色循环区虚线框，**组框自己变紫**（`#graph .node-group.is-loop`），标签写「组 · R1 · 循环 上限 3 · 已跑 3 轮」。点组 → 右栏组面板多出「循环区」一段：没声明时给 head/tail/上限 + 「声明为循环区（自动建回边）」；已声明时显示头尾/上限/已跑轮次 + 调高上限（master/lead）+ 撤销循环。
- **兼容**：老的 `POST /tasks/{id}/cycles {regionKey,...}` 还在，内部变成"按 regionKey 建/取同名组 → 给这个组声明循环"；建节点时传 `cycleRegion` 等于"加入同名组"。老库启动自动搬家（`MigrateLoopsIntoGroups`）。

## 九、双击快收快开 + 同向链与五合一

**接口与库一个字都没动**（主人原话：「只是前端显示整理——后端一直是那个代码」）。这两条都是画布上的看法，不是数据。

**① 双击标题＝快收快开**（三个对象一套手感）：

| 双击对象 | 效果 |
| --- | --- |
| 节点卡片（标题） | 完整卡片 ↔ 仅标题；本来停在「仅关键字」就摊回完整 |
| 组标签 / 收纳牌 | 组收成一块牌 ↔ 成员摊开 |
| 同向链块 | 5 个合 1 ↔ 摊开 |
| 空白 | 仍是「当场建一个默认节点」（没被上面三条抢走） |

节点收纳与组收纳本来就有落库的看状态（`nodes.compact`、`node_groups.collapsed`），双击只是加了个快入口。

**② 同向链（五合一）**：一串"一根筋接下去"的节点（A→B→C→D→E）可以收成一块宽卡，写上 `同向链 · 5 个合 1 · ×5`。

- **怎么算**：只看 `transfer` 边（回边不算）。从任意一节出发往回走：当前只有一条入边、且那条入边的上游只有这一条出边 → 再往前；顺下去同理。碰到分叉（多条出边）、汇合（多条入边）、跨节点组、或已经绕回来的节点就停。成员 ≥2 才是链。前端算，`walkChainLocal()` 与 `graphChains()` 同一套规则。
- **怎么收**：右键节点 →「同向链收成一块（N 个）」（N<2 时灰掉并写「同向上接不出第二个」）；点链块标题两下或面板按钮也能收/开。
- **怎么画**：链块落在**链头坐标**（`CHAIN_W=246`，高同节点），成员全部藏起来，链内部的线不画，两头跨界的线收拢到链块左右口（同一对只画一条，`×N`）。拖动链块＝整条一起挪（按住时把成员全选上，落库走老的 `POST /tasks/{id}/layout`）。摊开时三节以上画一圈虚线框标出这条链在哪（两节太吵，不画），选中的那条一定画。
- **状态只放内存**：`state.collapsedChains`（存链头节点 id），刷新就摊开。**这是刻意的**：不给它加表、不给它加接口；要长期记住再单独提。
- **不用手动维护**：链每次重绘按边现算。中途加线分叉、断线、节点被挪进别的组，链自己缩短或消失（页面断言里就有一条：删掉中间那条线，5 节变 2 节）。选中链块按 Delete＝摊开（节点与连线一个不少）。

## 十、预设：节点模板与组模板

- **两套预设、一张库**：`node_templates`（标题/一行目标/类型/进出线口数）与 `group_templates`（组名 + 节点列表 + 组内 transfer 线，坐标存**相对偏移**）。库**跨任务**，不挂在某个任务下。
- **怎么存**：右键节点 →「存成节点预设」（照这个节点快照）；组面板/组菜单「存成组预设」（照这个组快照，含组内线）。也支持直接给字段手写一个节点预设。
- **怎么套**：工具栏「模板库」列出两类，点「套用」落在**当前视野中心**（`centerWorld()`）；组预设按相对偏移整块落下，然后自动圈成同名组并选中。
- **组预设只带 transfer 线**：回边依附于"声明了循环的组"，跨任务套过去不可能成立，所以存模板时就把 loop 边滤掉，避免存一个"套了必报错"的模板。
- **组内线复用建线那一套**：套用时对每条线调 `AddEdge`，判重/端口/自动建规则组/上游已完工立刻放行全部一致——模板不是绕过规则的旁路。
- **套用不改已有节点**：落的是新节点、新线、新组；同一模板可以反复套。小坑：套出来的节点按"当前最大 seq + 1"排最后，`seq` 只影响自动布局与列表，不影响门判定。

## 十一、大图怎么看得清：按组整理 · 总览 · 束线（2026-10-28）

一百多个节点的图，"能画出来"和"看得清"是两件事。三个纯前端的看板工具（都不改语义）：

**① 按组整理（工具栏「按组整理」）**：整张图只有**一条「前后」主线**——组按跨组依赖排先后，一组一块、从左往右依次挨着放；组内也是从左往右，**一条流走到底不折行**（画布本来就没边，折成上下几条带会把"前后"读丢）。组内按**依赖分层**：

- 三个并行的节点站同一列，纵向摊开；
- 汇合节点自己占一列，**纵向对准那三份材料的重心**；
- 它再长出三条时，下一列就以它为中心上下摊开。

于是「1 → 3~4 → 1」在图上是一个看得出来的沙漏（就是主人给的那张样图），而不是一堆并排方块。组块之间纵向居中对齐，出口接下一个入口看起来是一条直线。算完照常落库（`POST /tasks/{id}/layout`），刷新还在。

**代价说实话**：一条线走到黑，整张图会很长（150 节点约 29000 px 宽），`重置视图`最多缩到 0.2，**一屏看不全**。所以全局看「总览」，细节用按组整理 + 横向平移，这是刻意的分工。

**② 总览（工具栏「总览」）**：把所有组收成牌，牌子按组的先后**排成一行**（前后排列，一行放不下才折），每块牌上直接写实情：`1 · 组 · A 需求与验收标准 / 16 个节点 · 完成 16 / 已收纳 · 双击展开`。颜色按状态：全完成绿、进行中蓝、**有阻塞红**；循环区的牌另写 `已跑 2/3 轮`。再点一次「总览」全摊开。

**③ 双击一块牌＝只摊开这一组**：其余组还是牌，视口自动框住这一组（一百多个节点同屏谁也看不清，**点开一组成焦点**才读得动）。换任务、展开某组都会自动退出总览。

**④ 组间束线（节点数 > 60 时自动开）**：一对组之间只画**一条**线标 `×N`（组内有几条线跨过来），不再是一条条曲线横穿画布；门控没点头的会标「门控待确认」。组内的线照旧一条条画——想看清具体哪根线，点开那一组或滚轮放大。

配套细节：组块之间留 240 间距（组框 + 标签都要地方），组标签上写 `16/16 完成 · 拖我`，阻塞的组标签底色变红。

## 十二、动作总表（做什么 → 落到哪）

| 动作 | 怎么用 | 落到哪 |
| --- | --- | --- |
| 拖节点 | 按住节点本体拖，松手即存；连线与组框实时跟随 | `POST /api/nodes/{id}/move` → `nodes.pos_x/pos_y`；没坐标的节点仍按深度自动排 |
| 框选多选 | 空白拖框；Shift 点击加/减选；多选后拖任意一个整组走 | `POST /api/tasks/{id}/layout`（一次写完，不 N 次往返） |
| 缩放 / 平移 | 滚轮 / 中键拖 / 重置视图 | 前端 `state.viewport`，不进库 |
| 新建任务 | 工具栏「＋ 新建任务」→ 标题 + 一行目标 | `POST /api/tasks`（空图），建完自动切过去 |
| 双击空白建节点 | 空白处双击 | `POST /api/tasks/{id}/nodes` 带 `x/y` |
| 点节点改属性 | 右栏「属性」改标题/目标/类型 | `POST /api/nodes/{id}/props`（写 `node-update` 事件） |
| 右键点节点 / 组标签 | 菜单：编辑属性、建组、删分组、删节点 | 菜单只是入口，动作走各自接口 |
| 右键按住连线 | 拖到目标松手成线（Shift＝回边） | `POST /api/tasks/{id}/edges`，失败原因走左下角提示条（6 秒消失） |
| 多选 + 建节点组 | 多选 ≥2 → 右键 →「建立节点组」 | `POST /api/tasks/{id}/node-groups` |
| 节点收纳 | 右键「收纳为仅标题 / 仅关键字 / 展开」 | `POST /api/nodes/{id}/compact` |
| 组收纳 | 组菜单/面板「收纳/展开」 | `POST /api/node-groups/{id}/collapse` |
| 点连线改它 | 右栏「连线」面板 | `POST /api/edges/{id}`、`/confirm`、`DELETE /api/edges/{id}` |
| 选中 + Delete | 节点 / 连线 / 组（多选逐个删并点名删不掉的） | `DELETE /api/nodes/{id}`、`/api/edges/{id}`、`/api/node-groups/{id}`，守卫全在后端 |
| 模板库 | 工具栏「模板库」套用 / 删除 | `GET /api/templates`、`POST /api/templates/{nodes,groups}`、`POST /api/tasks/{id}/apply-{node,group}-template` |

工具栏仍保留「＋ 新建节点 / ＋ 新建连线」两个表单入口（下拉选点，等同于点着用）；**检查点、拒因仍是只读**，认领/完成/检查点/择一/解除阻塞只能走 REST（验收脚本即此路径）。
